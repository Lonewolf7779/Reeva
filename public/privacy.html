Privacy Policy

Last updated: October 2026

1. Overview and Operational Model

Reeva is an open-source technical utility designed to allow users to retrieve and save publicly accessible media from supported online platforms for personal, educational, or archival use. This document outlines how the application operates from an engineering and data perspective.

2. Information Processed by Reeva

Reeva operates with minimal data collection principles built directly into its codebase:

  • Submitted URLs: When you provide a video link, the URL is submitted to the server to identify the platform, validate source domain rules, and query public media metadata. Reeva verifies that submitted URLs use secure HTTPS protocols and match permitted platform hostnames.
  • No User Accounts: Reeva does not provide user registration, user logins, profiles, or authentication accounts.
  • No Cookies or Tracking Scripts: Reeva does not set persistent tracking cookies, tracking pixels, or third-party analytics beacons in your browser. Language preferences, if chosen, are stored strictly on your device using local storage.

3. Media Storage and Temporary File Retention

Reeva is not a media hosting service and does not maintain a permanent library of downloaded videos or audio files:

  • Ephemeral Scratch Storage: When extraction requires server-side processing (such as format merging for combined streams), temporary artifacts are written to a restricted scratch directory (configured via REEVA_TEMP_DIR).
  • Automated Cleanup: Files in temporary scratch storage are assigned a short time-to-live (typically 10 minutes) and registered with an opaque identifier. An automated background cleanup daemon unlinks expired files from disk every 60 seconds. Files are also purged upon stream completion or server shutdown.
  • Direct Streaming: Whenever direct CDN access is supported by the source platform, media is proxied directly without saving bytes to disk storage.

4. Caching and Server Logging

  • In-Memory Caching: Extraction metadata (such as resolved stream URLs and title snippets) is cached in volatile server memory for up to 10 minutes to reduce redundant upstream requests and mitigate rate limits. Cached entries expire automatically and do not persist across server restarts.
  • Structured Event Logs: The server writes structured JSON logs for diagnostic and security auditing purposes. Log entries record timestamps, unique request correlation IDs, HTTP methods, status codes, duration, and error codes. URLs recorded in logs are sanitized to strip query parameters where feasible.
  • Rate Limiting: In-memory rate limiting monitors request volume per client IP address over short rolling windows (1 to 15 minutes) to protect service infrastructure from denial-of-service (DoS) attempts and resource exhaustion.

5. Third-Party Platform Interactions

When media is retrieved, Reeva makes outbound requests to the third-party platform hosting the requested content (e.g., YouTube, Instagram, TikTok, or Twitter/X). Those requests originate from the Reeva server infrastructure. Third-party platforms receive and process requests according to their own respective terms of service and privacy policies.

6. Information Requiring Operator Confirmation

Note for Users and Operators: Reeva is open-source software that may be hosted by independent operators. Specific deployment details depend on the operator's hosting environment:

  • Reverse Proxy / CDN Logs: If this instance is deployed behind a reverse proxy, CDN, or cloud provider (e.g., Cloudflare, AWS, NGINX), that provider may independently log client IP addresses and connection metadata according to its own retention policy.
  • Server Location & Jurisdiction: Physical server location and applicable data privacy regulations (such as GDPR, CCPA, or regional laws) are determined by the deployment operator.
